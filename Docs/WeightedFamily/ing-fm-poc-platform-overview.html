01The Origination Gap

Relationship Managers in Financial Markets origination spend hours each week assembling client pitchbooks manually. The work is repetitive, but the inputs are not standardised:

  • Signals arrive scattered across emails, Teams chat, news feeds, Houseview PDFs, and internal WorkFabric memos
  • Market data lives in one system, balance sheet data in another, credit ratings in a third
  • Every client needs a fresh narrative, fresh pricing, fresh compliance language
  • By the time a deck is drafted, the market window may have shifted

The cost is not just time. It is missed origination. A treasurer who needs a refinancing decision now does not wait three days for a draft. The RM who responds first usually wins the mandate.

The platform closes that gap. It reads the full signal corpus per client, anchors to the curated mandate already approved by the desk, and produces a deck that is ready for the client conversation, not for another round of internal editing.

It is delivered under the zero-fabrication principle: no invented numbers, no hallucinated pricing, no synthetic fallbacks. The audit trail is deterministic and inspectable.

Grounded Response

Read path. The frontend fetches /api/brand once on mount, then /api/opportunities. The backend reads from the database, applies brand substitution on ten text fields, and returns the client records. Fields like why_now, action, hv_doc_summary, and news_headline all pass through the same substitution layer.

Deck generation. POST /api/pitchbook/generate calls _set_active_brand before build_pitchbook. The deck builder reads its colours, logo, footer, and pillar text from the module-level brand slot and produces an 11-slide PPTX. Deck core_properties carry author, comments, timestamp, and title.

Mandate synthesis. On cache miss, the backend reads the curated anchor from ca_opportunity_scoring, fetches the twenty most recent signals, and calls Gemini with the anchor as the first instruction. The eight-key response travels through the 10-tuple cache to the API and the deck.

Copilot. POST /api/copilot/chat hydrates the prompt with both the pristine baseline deck state and the current active deck state, so the LLM reasons over exactly what the RM sees. It returns {reply, overrides}: the reply answers the question, the overrides mutate the deck.

06Multi-Agent LLM Layer

Extraction

Text in, structured signals out. Each ingestion yields multiple detected signals with metric, trigger, confidence, and urgency. Two-layer dedup prevents corpus pollution.

Synthesis

Anchor-first. The LLM produces the mandate narrative, a summary, a priority score, the product family, an adjacent-opportunities paragraph, and a concise primary_trigger. Drift guard replaces output with the anchor on tenor conflict.

Classification

The LLM proposes a product family. A weighted keyword vocabulary validates the proposal. Decisive override at score ≥ 5 with margin ≥ 3. Deterministic for the primary client.

Trigger Generation

Family-scoped prompt instructs the LLM to produce two semicolon-separated datapoint clauses under 180 chars. A five-rule deterministic validator accepts or rejects. Curated fallback on rejection.

Compliance

LLM audit of the full deck against MiFID II, MAR Article 11, and EU Green Bond Standard. Returns structured flags with slide number, rule, issue, and recommended overrides.

Copilot

Explains any slide, answers questions on the underlying data, runs audits, and edits the deck through chat. State mutations propagate to the preview and the exported deck.

Ingestion Deep-Dive

Page 4 of 8 · Ingestion

Five-channel ingestion with multi-signal extraction, two-layer deduplication, client-scoped source labelling, and cache invalidation on commit. Every ingestion commits to the database; the synthesis pipeline reads the accumulated corpus on the next request.

10Omni-Channel Ingestion

Five canonical channels. Each maps to a distinct ingestion path and a canonical source_channel value:

  • PDF_REPORT — Houseview PDFs and decks, extracted with pypdf and python-pptx
  • NEWS_RSS — live Google News RSS, per-client boolean search
  • CLIENT_EMAIL — Treasury and client correspondence
  • TEAMS_CHAT — internal deal channels
  • WORKFABRIC_MEMO — internal desk notes, latent opportunities

Legacy channel aliases (LIVE_RSS_NEWS, TREASURY_EMAIL, HOUSEVIEW) remain readable for historical data.

WorkFabric carries two signal types. Unlike the other channels, WorkFabric desk memos surface both detected signals and latent opportunities.

  • Detected signals — factual, dated events: a client authorized a bond programme, a competitor priced a green issuance, a maturity wall came into focus
  • Latent opportunities — softer observations: a coverage banker flagged hedge coverage erosion, a sector theme suggests refinancing urgency

Latent opportunities feed pillar 2 on Slide 3 and inform the adjacent-opportunities paragraph. The integration is designed for live API ingestion the moment WorkFabric exposes an endpoint.

11Two-Layer Dedup Guard

Layer 1 — Exact-match pre-check

Fast, deterministic. Requires both the source name and the content to match an existing row in the same channel. Distinct content passes through to Layer 2.

Prior behaviour: the pre-check used OR (source_name OR content), which caused any two emails from the same client to dedup because they shared the client-scoped source label. Corrected to AND on 22 Sep.

Layer 2 — Semantic LLM evaluation

Channel-scoped. The incoming content is compared against recent history in the same source_channel by Gemini, which decides DUPLICATE or UNIQUE.

Layer 2 is the content-aware gate. Layer 1 is a narrow fast path for exact duplicates.

12Client-Scoped Source Names & Cache Invalidation

Client-Scoped Source Names

When a UI ingestion arrives with an empty or sentinel source_name, the backend substitutes a client-scoped label derived from the resolved client display name:

  • TEAMS_CHAT → f"{cname} Teams Channel"
  • CLIENT_EMAIL → f"{cname} Treasury Email"
  • WORKFABRIC_MEMO → f"{cname} WorkFabric Memo"

Result: for BASF, the fallback produces "BASF SE Treasury Email" — not the pre-fix Enel-era hardcode. No cross-client contamination.

Cache Invalidation on Ingest

After every successful ingestion commit, the client's synthesis cache entry is popped:

_MANDATE_SYNTH_CACHE.pop(cid, None)

The next /api/opportunities call is a cache miss, runs fresh synthesis against the updated corpus, and repopulates the cache. The UI and deck reflect the new signal on the very next page load — no waiting for TTL.

14Mandate Synthesis — Eight Keys

why_now / action

Full narratives. why_now is 3 sentences (extended 22 Sep). action is 2 sentences. Feed Slide 3's Catalyst and Execution cards.

why_now_summary / action_summary

Max 160 characters each. Feed Slide 2's Window of Opportunity and Recommended Action cards.

priority_score

Integer 0–100. Weighted rubric: signal strength 40%, balance sheet pressure 30%, market window 30%. Written back to ca_opportunity_scoring.

family

One of FX_HEDGE, GREEN_ESG, RATES_HEDGE, DCM_REFI. Validated by the weighted vocabulary before the deck template is selected.

adjacent_opportunities

80–140 word grounded paragraph. Feeds Slide 3's third card and the Copilot's conditional response section. Validated deterministically; falls back to a curated paragraph on empty output.

primary_trigger (new)

Two semicolon-separated datapoint clauses under 180 chars. Feeds Slide 2's Primary Market Trigger card. Five-rule deterministic validator + curated fallback.

Anchor

The anchor (why_now_nlg + next_best_action) is the first instruction. Protected from LLM overwrite — only priority_score is written back.

Drift Guard

Deterministic post-synthesis check replaces LLM output with the anchor verbatim if conflicting tenors are detected. Prevents narrative drift.

Cache (10-tuple, 900s)

The full 8-key response plus expiry epoch and metadata. Populated after commit, invalidated on ingestion. Enables consistent preview-deck parity.

15Product Family Classification

The LLM proposes a product family. Before the pitchbook builder selects a template, detect_product_family validates the proposal against a weighted anchor score.

  • Weighted scoring. For each family, sum the weights of every keyword present in why_now_nlg + next_best_action. Strong product signals (weight 5: green bond, slb, emtn, irs pre-hedge, fx collar) dominate weak context words (weight 1–2: refinancing, maturity wall, dual-tranche).
  • Decision logic. If the top family's score is ≥ 5 with a margin ≥ 3 over the runner-up, the weights override the LLM — deterministic. Otherwise, the LLM's judgment stands.

Rationale

A naive keyword classifier fails when a narrative legitimately mentions multiple families — for example, an EMTN bond with a greenium feature trips both DCM and Green vocabulary.

The weighted hierarchy encodes the taxonomy: the product dominates the purpose or feature. The LLM reads the full anchor; the weights enforce the hierarchy.

Observed: primary client scores 15 Green vs 5 DCM — decisive override. Secondary client scores 8 DCM vs 5 Rates — at threshold; LLM decides.

LLM-Generated Primary Trigger

Page 6 of 8 · Trigger

Slide 2's Primary Market Trigger card is now populated by a dedicated LLM-generated field rather than a curated database value. Family-scoped prompt + deterministic validator + curated fallback chain gives both intelligence and control.

16How the Trigger is Generated

1. Family-Scoped Prompt

The synthesis prompt receives a family-scoped instruction block — FAMILY_PRIORITY_SIGNALS + FAMILY_CONTEXT_SIGNALS — that steers the LLM toward datapoints most relevant to the resolved family.

For GREEN_ESG: eligible green asset pool, debt maturity wall, board authorization, indicative greenium.

2. Format Rules

Two semicolon-separated datapoint clauses. Under 180 characters. Each clause contains a number and a unit. No marketing adjectives.

Good: "€3.5bn eligible green asset pool; €10.13bn maturity wall across 2026-2027"

Bad: "Indicative Greenium: -5 bps; offering a clear pricing advantage"

3. Five-Rule Validator

_validate_primary_trigger checks deterministically:

  1. Non-empty, ≤ 180 chars
  2. Exactly one semicolon
  3. Digit in both clauses
  4. No marketing words
  5. Top family from weighted scoring matches resolved family

17Fallback Chain & Read Path

Fallback Dict on Rejection

If the validator rejects the LLM's output, _resolve_primary_trigger substitutes a curated value in this order:

  • Per-client entry from PRIMARY_TRIGGER_FALLBACKS (CLI101, CLI103)
  • Per-family entry (prefixed with _)
  • Literal "Active capital structure optimization"

Every rejection logs the specific rule that failed — no silent fallbacks.

Read Path Precedence

Deck (pitchbook_builder.py) and preview (App.jsx) both follow the same chain:

  1. Session override — ov["trigger"] / deckOverrides.trigger
  2. LLM-generated — ctx["primary_trigger"] / opp.primary_trigger
  3. Curated DB value — ctx["trigger_source"]
  4. Family default — hardcoded per family

19Cold-Cache Behaviour

The primary_trigger is LLM-generated only when the synthesis cache has been warmed within the last 900 seconds. On a cold cache, the deck and preview fall back to the curated trigger_source value from the database.

The RM workflow loads the dashboard first — which triggers synthesis and warms the cache. So in practice the trigger is always the LLM-generated value by the time the deck is downloaded.

Cache Invalidation Guarantees Freshness

Two events invalidate the cache:

  • TTL expiry — 900 seconds
  • Signal ingestion — pop(cid, None) after commit

A freshly ingested signal flips the trigger on the very next page load. No waiting.

Copilot, Compliance & Branding

Page 7 of 8 · Interactions

Three user-facing capabilities that turn the platform from a data pipeline into an origination workspace: the Copilot answers questions and mutates state, compliance runs at the deck level, and the runtime brand toggle lets the same platform present as multiple brands.

20Pitchbook Copilot

Context hydration. POST /api/copilot/chat builds the system prompt with two full deck snapshots: the pristine baseline_deck_slides and the current active_deck_slides. The LLM reasons over exactly what the RM sees, plus the original, unmodified state.

Structured response. The Copilot returns {reply, overrides}. The reply is consultative prose. The overrides object carries state mutations — changing a spread, updating a yield, adjusting a greenium concession — which the frontend merges into deckOverrides and re-renders.

What the RM can ask.

  • "Explain Slide 3" — produces the three mandatory sections plus a conditional fourth when adjacent opportunities exist
  • "Run MiFID II, MAR and EU Green Bond Standard compliance audit" — returns structured flags
  • "In Slide 7, update Bund yield to 2.65%" — mutates the deck through the overrides payload
  • "Apply compliance recommendations" — executes remediations returned by the audit

Encoding discipline. Serialization uses json.dumps(..., ensure_ascii=False) so real € characters reach the LLM. Prior to this fix, the Copilot occasionally echoed \u20ac in replies for Slide 3.

21Compliance Architecture

MiFID II (Art. 24/54)

Professional clients only. Mandatory proximate non-binding pricing disclaimer on Slide 8. The audit flags missing or insufficient caveats.

MAR Article 11

Market Sounding safe harbour disclosure. Required on Slide 11 for any pre-hedge or pre-pricing conversation.

EU Green Bond Standard

Second-Party Opinion verification, use-of-proceeds pool eligibility, EU Taxonomy alignment. Applies to Green/ESG decks.

EMIR

Derivative classification for pre-hedge swaps. NFC+ determination for the hedging counterparty.

Structured Flags

Each flag carries slide_number, rule, issue, and recommended_overrides. The RM can apply remediations with one click.

One-Click Remediation

The remediation payload returns pricing_caveat, emir_notice, compliance_status, and additional disclaimers that merge into deckOverrides.

22Runtime Brand Toggle & Brand Onboarding

One codebase, three live services. The same Docker image deploys as ing-fm-poc-service (ING branding), bfs-ai-lab-service (BFS AI Lab branding), and acme-service (Acme Financial branding). The only difference is the BRAND environment variable.

27 keys per profile. Display strings, logo filenames, logo render height, footer, attribution, houseview fallbacks, RSS URL, eight colour keys, five LLM persona strings, filename prefixes. All three brands carry the identical key set — verified programmatically.

Colour palette. ING: orange #FF6200 and navy #000066. BFS AI Lab: turquoise #10C4C0 and navy #0A3168, extracted from the logo PNG via pixel census. Acme Financial: maroon #701C36 and oxblood #3A0E1D.

Frontend CSS variables. Seven custom properties set on document.documentElement after the brand fetch. 130 hardcoded hex values in the React app now reference these variables. Download filenames, browser tab titles, and loading text all follow the active brand.

Cache & Single-Instance Rationale

The mandate synthesis cache is in-memory (900s TTL, invalidated on ingest). This requires max-instances=1 per service. At production scale, the cache would move to a shared store such as Redis or a DB-backed layer.

25Verification Discipline

13-Gate Parity Audit

Runs before every deploy. Validates database connectivity, market rate ground truth, credit spread ground truth, API integrity, bundle consistency, PPTX generation, and non-destructive invariance. Any code change must maintain 13/13 passing gates.

Recovery & Snapshots

Every milestone is tagged and locally backed up. Baseline snapshots are regenerated after any DB content change that should survive a reset. Recovery tags on the branding branch preserve states before and after each major change.
