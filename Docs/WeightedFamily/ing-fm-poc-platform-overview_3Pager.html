01The Origination Gap

Relationship Managers in Financial Markets origination spend hours each week assembling client pitchbooks manually. The work is repetitive, but the inputs are not standardised:

  • Signals arrive scattered across emails, chat, news feeds, and internal memos
  • Market data lives in one system, balance sheet data in another
  • Every client needs a fresh narrative, fresh pricing, fresh compliance language
  • By the time a deck is drafted, the market window may have shifted

The cost is not just time. It is missed origination. A treasurer who needs a refinancing decision now does not wait three days for a draft. The RM who responds first usually wins the mandate.

The platform closes that gap. It reads the full signal corpus per client, anchors to the curated mandate already approved by the desk, and produces a deck that is ready for the client conversation, not for another round of internal editing.

Grounded Response

Read path. The frontend fetches /api/brand once on mount, then /api/opportunities. The backend reads from the database, applies brand substitution on ten text fields, and returns the client records.

Deck generation. POST /api/pitchbook/generate calls _set_active_brand before build_pitchbook. The deck builder reads its colours, logo, footer, and pillar text from the module-level brand slot and produces an 11-slide PPTX.

Mandate synthesis. On cache miss, the backend reads the curated anchor from ca_opportunity_scoring, fetches the twenty most recent signals, and calls Gemini with the anchor as the first instruction. The seven-key response travels through the cache to the API and the deck.

Copilot. POST /api/copilot/chat hydrates the prompt with the active and baseline deck state, so the LLM reasons over exactly what the RM sees.

06Multi-Agent LLM Layer

Extraction

Text in, structured signals out. Each ingestion yields multiple detected signals with metric, trigger, confidence, and urgency. Two-layer dedup prevents pollution.

Synthesis

Anchor-first. The LLM produces the mandate narrative, a summary, a priority score, the product family, and an adjacent-opportunities paragraph. Drift guard replaces output with the anchor on tenor conflict.

Classification

The LLM proposes a product family. A weighted keyword vocabulary validates the proposal. Decisive override at score ≥ 5 with margin ≥ 3. Deterministic for the primary client.

Compliance

LLM audit of the full deck against MiFID II, MAR Article 11, and EU Green Bond Standard. Flags issues per slide and proposes remediations the RM can apply with one click.

Copilot

Explains any slide, answers questions on the underlying data, runs audits, and edits the deck through chat. State mutations propagate to the preview and the exported deck.

Deck Metadata

Every generated PPTX carries author, comments, creation timestamp, and title in its file properties, visible in File → Info on any desktop.

Key Implementations & Benefits

Page 3 of 3 · Outcomes

What was built, why it matters, and what comes next. Grounded engineering, deployed on Google Cloud, governed by the zero-fabrication principle at every layer.

07Key Implementations

Zero Fabrication Discipline

Every displayed value traces to a specific database row filtered by client_id. The LLM extracts and synthesises but never invents. Three enforcement layers: anchor-first prompt structure, deterministic drift guard, read-path validation.

Anchor Pattern for Synthesis

The curated mandate in ca_opportunity_scoring is the anchor. The LLM reads it first, then the signal corpus. A drift guard replaces output with the anchor verbatim if conflicting tenors are detected. Narratives cannot drift from the desk-approved structure.

Weighted Family Classification

The LLM proposes a product family. A curated weighted vocabulary validates it. Strong product signals (weight 5) dominate weak context words (weight 1 to 2). When decisive, the weights override the LLM. When not, the LLM's judgment stands.

Grounded Adjacent Opportunities

Beyond the primary mandate, the platform surfaces cross-sell angles from the same signal corpus. Each adjacency cites a specific signal. No invention, no repetition, no marketing language. Maximum three angles, prioritised by notional or urgency.

Pitchbook Copilot

Explains any slide in context, answers questions on the underlying data, runs MiFID II and MAR compliance checks, applies remediations, and edits the deck through chat. State mutations propagate to both the preview and the exported PPTX.

Runtime Brand Toggle

Same codebase, same database, two Cloud Run services. A single BRAND environment variable selects the profile: colours, logos, footers, Copilot name, prompt personas, download filename. ING remains the default when the variable is unset.

08Business Benefits

  • Time to first draft — minutes instead of days. The RM goes into the client meeting with a grounded, compliance-aware deck already prepared.
  • Zero fabrication risk — every number in the pitchbook is auditable back to a database row. No hallucinated metrics reach the client.
  • Full-corpus origination — the platform surfaces adjacent opportunities the RM might miss, grounded in the same signal corpus.
  • Compliance built in — MiFID II, MAR, and EU Green Bond Standard audits run at the deck level with one-click remediation.
  • Regulatory transparency — the audit trail is deterministic. Every LLM call is anchored, every output is validated, every mutation is logged.
  • Brand flexibility — the runtime toggle lets the same platform present as ING, BFS AI Lab, or a future brand without a code fork or a second database.
  • Operational simplicity — the entire stack runs serverless. Zero infrastructure to maintain, cold start under six seconds.
  • Extensible architecture — new signal channels, new product families, and new LLM capabilities plug in without rewriting the core pipeline.

09Deployment & Delivery

Infrastructure

Google Cloud Run in europe-west1, 1 vCPU and 512 MiB per instance, single warm instance per service. Cloud SQL PostgreSQL 15 with pgvector. Vertex AI for all LLM and embedding calls. Secrets in Google Secret Manager.

Two Services, One Image

The ing-fm-poc-service and bfs-ai-lab-service run the same Docker image, connect to the same database, and differ only by the BRAND environment variable. Both live, both verified end to end.

Operational Maturity

Thirteen-gate parity audit runs before every deploy. Syntax verification, whitelist sync, dictionary sync, and structural checks all automated. Archive of recovery tags and local backups at every milestone.

10What Comes Next

Real-time WorkFabric ingestion. The platform currently ingests WorkFabric signals and latent opportunities via the ingestion engine. The integration is designed for live API ingestion the moment an endpoint is exposed. No code change required, the ingestion engine already speaks the target shape.

Live client data pipeline. The seed layer is populated today. The next step is a governed pipeline from the client's treasury systems into the read layer, keeping the zero-fabrication discipline intact.

Multi-client scaling. The whitelist currently scopes the demo to one primary client. The synthesis cache, ingestion dedup, and brand substitution all support multiple clients, so the platform is ready to scale the demo corpus when needed.

Statistical refinement of the family classifier. The weighted vocabulary is hand-curated and defensible today. As the platform accumulates classified anchors, the weights could be refined statistically without changing the interface.
